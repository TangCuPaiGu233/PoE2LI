# PoE2LI 扩充版 Eval 评测集（题目清单 + 评分口径）

> 配套文档：`PoE2LI-解决思路-当前需求.md` 第 7 节
> 目标：把"改前先拿基线、改后看 diff"落成一份**可直接执行的评测集**。覆盖四大需求引入的新风险维度，每题给出 query、考察点、期望要点、判定口径。
> 用法：每改一个需求跑全量，输出 pass/fail + 各维度通过率 + 与基线 diff。

---

## 0. 评测集结构与机器可读格式

每条用例的标准字段（建议存为 `eval/cases.jsonl`，一行一条）：

```json
{
  "id": "ENT-001",
  "dim": "entity_recall",         // 维度
  "query": "猎巫人是什么职业的升华？",
  "must_include": ["佣兵"],       // 回答必须命中的要点（AND）
  "must_not_include": ["女猎手", "游侠"],  // 出现即判错（防跨职业误推）
  "expect_relation": {"src":"ascendancy:witchhunter","relation":"belongs_to","dst":"class:mercenary"},
  "intent": "entity",             // 期望 intent 分类
  "max_latency_sec": 30,
  "note": "回归 bug：猎巫人曾被错推给女猎手"
}
```

判定逻辑（建议）：
- `must_include` 全部命中 且 `must_not_include` 全部未出现 → 内容通过；
- `expect_relation` 用于校验图谱边是否存在（直接查 kb_edges，不依赖 LLM 措辞）；
- 延迟单独统计 P50/P95；
- 经验类用例额外校验"是否带来源/主观度标注"。

## 1. 维度一：实体召回（entity_recall）—— 根治"实体漏掉"

核心：12 职业 / 36 升华全覆盖，重点覆盖曾缺失实体。

| id | query | must_include | must_not_include | note |
|----|-------|--------------|------------------|------|
| ENT-001 | 列出所有职业 | 战士,女巫,游侠,僧侣,佣兵,女猎手 | — | 职业全覆盖 |
| ENT-002 | 女猎手有哪些升华？ | （该职业全部升华名） | 其他职业升华 | 曾缺失实体 |
| ENT-003 | 猎巫人是哪个职业的升华？ | 佣兵 | 女猎手,游侠 | 回归 bug |
| ENT-004 | 行者这个升华怎么样？ | 行者 | "未找到","不存在" | 曾缺失实体 |
| ENT-005 | 介绍一下佣兵职业 | 佣兵 | — | 核心职业 |
| ENT-006 | 一共有多少个升华职业？ | 36 | — | 数量校验 |
| ENT-007 | 僧侣的升华有哪些？ | （僧侣全部升华） | — | 全覆盖 |
| ENT-008 | 闪电箭是什么技能？ | 技能,闪电 | "未找到" | 技能实体 |

判定补充：ENT-001/006/007 这类"全覆盖"题，用 must_include 列全名单 + 校验数量。

---

## 2. 维度二：关系正确（relation_correct）—— 不跨职业误推

核心：升华推荐、归属、依赖关系不出错。直接查 `expect_relation` 比对图谱边。

| id | query | expect_relation / 校验点 | must_not_include |
|----|-------|--------------------------|------------------|
| REL-001 | 给女猎手推荐升华 | 推荐项的 belongs_to 必须=huntress | 任何非女猎手升华 |
| REL-002 | 猎巫人属于哪个职业 | witchhunter belongs_to mercenary | 女猎手 |
| REL-003 | 这个辅助宝石能支持哪些技能 | edge: support--supports-->skill 存在 | — |
| REL-004 | 这把暗金武器基于什么基底 | unique--based_on-->base_item 存在 | — |
| REL-005 | 给战士推荐升华 | 推荐项 belongs_to=warrior | 法术系升华 |
| REL-006 | 这个技能需要什么武器 | skill--requires_weapon-->X | — |

判定补充：REL-001/005 推荐类题，遍历回答中提到的所有升华，逐个校验 belongs_to，任一不符即 fail（关系错误率→0 的红线）。

---

## 3. 维度三：中英 / 多服映射（name_mapping）—— 俗名也能命中

核心：中文俗名、繁中、腾讯服译名都能归一到同一 canonical 实体。

| id | query | must_include | 校验点 |
|----|-------|--------------|--------|
| MAP-001 | Lightning Arrow 是什么 | 闪电箭 | en→实体命中 |
| MAP-002 | 闪电箭的英文名 | Lightning Arrow | cn→en 映射 |
| MAP-003 | 畸变项链是什么 | （对应 canonical 实体描述） | 腾讯译名命中 |
| MAP-004 | 扭曲项链和畸变项链是一个东西吗 | （正确区分/说明） | 易混实体 |
| MAP-005 | （繁中俗名）查询 | 对应实体 | zh-tw 命中 |
| MAP-006 | 混沌石是什么通货 | （混沌石描述） | 通货映射 |

判定补充：MAP 类核心看"是否命中正确 entity_id"，可在检索层埋点记录命中的 entity_id 与期望比对，比看 LLM 措辞更稳。

---

## 4. 维度四：百科去混淆（disambiguation）—— 易混实体不串

核心：名字相近/概念相近的实体对，绝不张冠李戴。

| id | query | must_include | must_not_include |
|----|-------|--------------|------------------|
| DIS-001 | 扭曲项链的属性 | （扭曲项链真实属性） | 畸变项链属性 |
| DIS-002 | 畸变项链的属性 | （畸变项链真实属性） | 扭曲项链属性 |
| DIS-003 | 这两个名字像的暗金有什么区别 | 正确区分两者 | 把属性张冠李戴 |
| DIS-004 | （同名不同类实体）查询 | 正确类型 | 错误类型实体 |

判定补充：DIS 类是幻觉重灾区，must_not_include 命中即 fail，目标"混淆幻觉→0"。

---

## 5. 维度五：经验区分（experience_separation）—— 事实经验不混淆

核心：经验类回答必须标注来源/主观度，且不冒充官方数据。

| id | query | must_include | 校验点 |
|----|-------|--------------|--------|
| EXP-001 | 这把武器适合开荒吗 | "玩家经验"/"个人观点"标注 | 经验须标主观度 |
| EXP-002 | 闪电箭配什么辅助好 | 来源标注（作者/赛季） | works_with 经验边 |
| EXP-003 | 这把武器和那把哪个强 | "主观比较"/赛季标注 | better_than 经验边 |
| EXP-004 | 这个词缀值得做吗 | 区分官方数据 vs 经验 | 不混淆 |
| EXP-005 | 一个纯官方数据问题（如某技能基础伤害） | "官方数据" | 不应标成经验 |

判定补充：
- EXP-001~004：回答中"经验性结论"必须伴随来源或主观度标注，否则 fail；
- EXP-005：反向用例——纯事实题不应被错误标注为经验。

## 6. 维度六：延迟（latency）—— P50 < 30s

不单独造题，复用上述全部用例统计：

| 指标 | 目标 |
|------|------|
| P50 端到端延迟 | < 30s |
| P95 端到端延迟 | < 45s（软目标） |
| 实体型 query（ENT/MAP/DIS） | 应更快（精确路命中） |
| 受控扩展触发率 | 仅"精确未命中"题触发，监控异常飙升 |

判定补充：每题记录 `latency_sec` 与各阶段耗时（intent/召回/rerank/扩展/LLM），便于定位瓶颈。

---

## 7. 维度七：幻觉率回归（hallucination）—— 不低于基线

核心：保留历史已知幻觉用例（如 baseline build_001 残影类），确保新改动不引入旧幻觉。

| id | query | must_not_include | note |
|----|-------|------------------|------|
| HAL-001 | （历史幻觉触发 query 1） | （被幻觉出来的错误内容） | 回归保护 |
| HAL-002 | （历史幻觉触发 query 2） | （错误内容） | 回归保护 |
| HAL-003 | 一个游戏里不存在的实体（如"虚空法杖XYZ"） | "不存在"/"未找到"应出现，禁止编造 | 拒答能力 |

判定补充：HAL-003 是关键——问不存在的东西，**正确行为是承认不知道**，编造即 fail。

## 9. 执行与集成建议

- 把 `cases.jsonl` 纳入 git，与代码同仓版本化。
- 每个需求 PR 必须附 eval diff 报告，**新增 fail 不合并**。
- 内容判定（must_include/not_include）做成 `evaluator.py`，关系判定直接查库（绕开 LLM 措辞噪声），延迟从端到端埋点取。
- 经验维度（EXP）需要先有少量经验数据灌入才能跑，可在需求3 落地前先标 `skip`，落地后启用。
- 建议加一个 `golden/` 目录存"标准答案要点"，方便人工 review 与回归对照。
