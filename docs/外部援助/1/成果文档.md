# PoE2「流放漓」AI 推荐问答系统 — 成果交付文档

> 日期：2026-06-09
> 需求：以 poe2db.tw（流放2编年史）为知识库，实现 AI 推荐问答。
> 典型问题：「这 10 个传奇哪个最适合我的死灵法师？」AI 给出正确、可解释的推荐。
> 项目仓库：https://github.com/TangCuPaiGu233/PoE2LI

---

## 一、今天做了什么（TL;DR）

在现有 RAG 问答系统基础上，**叠加了一层"推荐 Agent"**，让系统从"百科查询"进化到"对比推荐"。

完成三块工作：
1. **方案设计** — 摸清现有架构，定位真实缺口，出技术方案
2. **核心代码** — 推荐 Agent + API 接口 + 实体词典，全链路自测跑通
3. **数据 + 前端** — 从 poe2db 爬全量 446 传奇做词典，配套对比卡片 UI 原型

---

## 二、关键诊断（最有价值的结论）

扒了项目的 `CLAUDE.md` 后发现一个重要事实：**RAG 问答系统其实已经搭好了**。

| 已就位（无需重做） | 缺口（本次补齐） |
|---|---|
| poe2db 1249 三语 chunk + BGE-M3 向量 | 意图路由（百科 vs 推荐） |
| 向量检索 + 关键词预分类 | 实体解析（职业/升华/流派/候选项） |
| DeepSeek LLM 生成 + Redis 缓存 | 多路并行召回 |
| trade_agent 成熟 Agent 范式 | 适配性打分 + 排序 |
| PoB Code 结构化数据（BuildData） | 个性化上下文注入 |

核心矛盾：现有系统是 `single-hop encyclopedia lookup`（单跳百科查询，官方文档原话），而"哪个传奇最适合死灵法师"是**多跳 + 对比 + 个性化推荐**。

**解法：叠加而非重建，零数据库迁移。**

## 四、系统架构

```
用户提问 (+可选 PoB Code)
   │
   ▼
┌─────────────────────┐
│ 意图路由 route_intent│  规则/LLM：encyclopedia | recommend
└─────────┬───────────┘
   ┌───────┴────────┐
   ▼                ▼
现有 /ask        新增 /api/knowledge/recommend
单跳RAG               │
                      ▼
              ┌──────────────────┐
              │ RecommendAgent   │
              │ 1 parse_intent   │ 抽 职业/升华/流派/候选项/预算
              │ 2 resolve_entities│ 别名→标准名
              │ 3 build_context  │ PoB BuildData 个性化注入
              │ 4 multi_retrieve │ 每个候选并行向量召回
              │ 5 score_each     │ LLM 逐项打分 (JSON schema)
              │ 6 rank_and_explain│ 排序 + 总结理由
              └────────┬─────────┘
                       ▼
              结构化 JSON → 前端对比卡片
```

### 三路候选来源（优先级链）
1. `user` — 用户显式指定候选传奇列表
2. `page` — 页面上下文带入（在某传奇分类页发问）
3. `mention` — 从问题文本里识别真实传奇名（命中全量词典）
4. `auto` — 按流派标签从 446 传奇库自动召回

## 五、数据成果

从 poe2db 真实爬取，词典从「手填 10 个种子」升级为全量数据：

- **446 个传奇物品**（对得上页面 88+221+139 总数）
- **82 个升华职业**
- **7 类流派自动打标**：
  - cold 109 / ignite 107 / lightning 92 / physical 82 / poison ~ / crit ~ / **minion 20**

实测验证：
- 问「死灵法师」→ auto 召回 10 个真实 minion 传奇（霜息、渡鸦之群、血肉傀儡…）并排序 ✅
- 问「渡鸦之群和血肉傀儡哪个好」→ 精准识别两个真实传奇 ✅
- 点燃向「腐化之心」对死灵被正确判为 35分[不推荐]，召唤向「九尾灵猫」90分[强烈推荐] ✅

## 六、接口定义

### `POST /api/knowledge/recommend`

请求：
```json
{
  "question": "这10个传奇哪个最适合我的死灵法师？",
  "pob_code": "eNp...",
  "candidates": ["渡鸦之群", "..."],
  "page_candidates": ["..."],
  "league": "奥杜尔秘符",
  "game_version": "0.5.1"
}
```

响应：
```json
{
  "intent": "recommend",
  "resolved": { "class": "Witch", "archetype": "死灵(召唤)", "ascendancy": "深渊巫妖", "candidate_source": "auto" },
  "ranking": [
    { "name": "渡鸦之群", "fit_score": 92, "pros": ["召唤生物伤害+80~120%"],
      "cons": ["需65级"], "synergy": "死灵召唤核心杖", "verdict": "强烈推荐",
      "sources": [{ "chunk_type": "item", "similarity": 0.86 }] }
  ],
  "best_pick": "渡鸦之群",
  "summary": "对死灵召唤流而言...",
  "disclaimer": "基于 poe2db 当前赛季数据，实战需结合个人构建验证。"
}
```

## 七、接入工程步骤（3 步）

1. 把 `recommend/` 三个 py 文件挪进 `backend/app/`
   - `recommend_agent.py` / `entity_dict.py` / `entity_data.py` → `services/`
   - `api_recommend.py` → `api/`
   - 两个 JSON 数据文件随 `entity_data.py` 同目录放置
2. 解除 `api_recommend.py` 里的 import 注释，接上真实的 `embed_text` / `retrieve_similar` / `chat_completion` / `decode`
3. `main.py` 加一行 `app.include_router(recommend_router)`

前端：把 `recommend_cards_demo.html` 里的 `DATA` 换成 `fetch('/api/knowledge/recommend')` 即可。

## 八、下一步建议（按优先级）

1. **【高价值】扒全 446 传奇完整词缀灌入向量库**
   poe2db 传奇详情页用 `data-hover` 懒加载完整词缀。把这批高质量词条扒下来喂进 `knowledge_chunks`，推荐打分召回的就是真实完整词缀而非页面摘要——对准确度是质变。
2. **PoB Code 个性化深度接入**
   `_build_user_context` 已留接口，接上 `pob_decoder.decode` 后可读职业/升华/已用技能做约束。
3. **多轮对话追问**
   候选/流派/预算缺失时，AI 反问补全（P3 阶段）。
4. **意图路由调优**
   现用关键词触发词，量大后可换轻量分类模型降误判。

## 九、设计原则（继承自项目铁律）

- 打分只能基于召回的 poe2db 资料，**禁止编造词条/数值**
- 输出固定 JSON schema，校验失败则 retry
- 所有召回带 `league + game_version` 过滤，杜绝旧赛季数据污染
- 适配性=LLM 推理产物，但 pros/cons 必须引自召回资料
