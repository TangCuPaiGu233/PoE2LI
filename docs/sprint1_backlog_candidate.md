> 版本: v0.1 | 状态: 草案 (待方向对齐会讨论)

---

## 一、总体 Sprint 目标

**双线并进，第一周有看得见的产出：**

1. **后端**：建立测试基础设施，保障现有 API 稳定运行
2. **前端**：打磨现有页面体验，对接真实后端 API
3. **基建**：搭起 CI/CD 骨架，降低集成风险

对应 KR 维度：后端稳定性 → KR2 | 前端体验 → KR4 | 数据流水线 → KR5

## 四、风险 & 缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| LLM API 调用在测试中成本过高 | 中 | 高 | BE-03 使用 mock LLM 响应，不真实调用 |
| Chat 页面 671 行耦合度过高 | 高 | 中 | FE-03 先做交互优化，重构可延后到 Sprint 2 |
| 游戏数据版本更新导致测试失败 | 低 | 中 | BE-02/03 使用固定 seed 数据而非实时数据 |
| 前端 API 对接发现后端接口不一致 | 中 | 中 | FE-02 与 BE-04 联动，对齐后统一修复 |
