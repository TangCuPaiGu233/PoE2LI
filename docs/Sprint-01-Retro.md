## 四、What Could Improve 🔧

1. **Phase 1b 未能完全收尾** — PoB golden data 测试 + API 集成测试推到 Sprint 2
   - 原因：Phase 1a 复杂度略超预期（conftest 依赖链调试），吃掉 Phase 1b 时间
   - 建议：Sprint 2 排 Phase 1b 时预留 buffer

2. **覆盖率未达标（36% < 50%门禁）** — 6 个失败测试待探查 + coverage gap
   - 原因：Phase 1a 只建了测试框架，大量代码仍无测试覆盖
   - 建议：Sprint 2 Phase 1b 集中火力补 PoB 解码 + API 集成测试覆盖

3. **工程师 worktree 流程** — 创建 worktree 需要朝露操作，有 1 次等待
   - 建议：Sprint 2 评估是否授予 PM worktree 创建权限，减少等待

4. **文档同步机制刚建立** — 本次 B4 对账发现了 2 处实质性矛盾
   - 建议：Sprint 2 开始执行「每次 PR merge 前文档一致性检查」

5. **FE-03 范围仍偏大** — 虽然加了边界控制，但 Chat 页 671 行范围打磨还是占了较多时间
   - 建议：Sprint 2 FE 任务拆更细（loading/空态/错误/滚动 拆 4 个独立 task）

6. **NAS 执行权限阻塞** — 拾遗 TC 导出需 NAS SSH 访问，但数据工程师无此权限
   - 建议：明确 NAS 执行责任人（远岫/织墨/朝露），避免数据轨道交付被权限卡住
