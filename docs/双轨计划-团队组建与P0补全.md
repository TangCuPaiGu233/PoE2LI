## 轨道A：招人 —— 团队组建

### 目标
补齐开发团队，让项目从「架构师单兵作战」进入「工程团队协作」阶段。

### 招聘岗位（优先级排序）

| 优先级 | 岗位 | 归属管理 | 关键技能 | 预期产出（入职后2 project days内） |
|:---:|------|---------|---------|--------------------------------|
| P0 | 后端工程师 | 远岫 | FastAPI、Python、PostgreSQL、Celery | 独立维护BE API + 修复已知 bug |
| P0 | 前端工程师 | 远岫 | Next.js、React、TypeScript、TailwindCSS | 独立迭代 FE 页面 + 补充 Trade UI |
| P1 | AI Agent 工程师 | 远岫 | LLM 编排、RAG、Prompt 工程、向量数据库 | 优化 AI 输出质量 + 维护 Agent 管道 |
| P1 | 数据工程师 | 远岫 | ETL、爬虫、数据治理、GGPK 管道 | 维护数据采集 + 知识库更新 |

### 时间线（预估）

| 里程碑 | 项目时间 | 真实时间参考 |
|--------|---------|------------|
| JD 确定（远岫+织墨对齐） | Day 0 | 即时 |
| 流星赶月开始走招聘流程 | Day 0-1 | 0-15 min |
| P0 岗位（后端+前端）到位 | Day 2-3 | ~30-45 min |
| P1 岗位（AI+数据）到位 | Day 3-5 | ~45-75 min |
| 团队磨合期完成，首个 Sprint 启动 | Day 5 | ~75 min |

### 入职流程
1. 岗位 JD 确定（远岫定义技术要求 + 织墨定义协作要求）
2. 流星赶月执行招聘
3. 入职后：先读 CLAUDE.md + CONTEXT.md + 技术架构评估 → 配开发环境（worktree）→ 首个简单 task

## 轨道B：P0补全 —— 质量门禁 + 冷启动 + 技术债清理

### 目标
让 P0 闭环从「功能上能跑」变成「真正可交付用户使用」。

### 待办清单

| 编号 | 任务 | 优先级 | 预估工时（人·天） | 依赖 |
|:---:|------|:---:|:---:|------|
| B1 | 建立质量仪表盘：解码成功率/攻略生成成功率/平均延迟 | P0 | 0.5 | B2 完成后上线跑数据 |
| B2 | M2 人工抽检流程 + Prompt 迭代闭环 | P0 | 1 | 后端/AI 工程师到位 |
| B3 | 冷启动内容导入：手动导入 N 个热门 Build | P0 | 0.5 | B2 完成 |
| B4 | 文档版本对账：CLAUDE.md / HANDOVER.md / ADR 一致性修复 | P0 | 0.5 | 无（织墨+远岫即可做） |
| B5 | Docker 镜像重建（替代 docker cp 热修复） | P1 | 1 | 后端/运维工程师 |
| B6 | Trade 搜索结果前端页面 | P1 | 1 | 前端工程师 |
| B7 | 已知技术债清单梳理 → 纳入 Backlog | P0 | 0.5 | 远岫技术评估产出后做 |

### 执行顺序

```
Day 0-1: B4（文档对账，织墨+远岫可并行）
         B7（技术债梳理，依赖远岫评估）
         
Day 2-3: B2（质量门禁，团队到位后）
         B1（仪表盘，与B2同步）
         
Day 3-4: B3（冷启动导入）
         B5（Docker重构）
         
Day 4-5: B6（Trade UI）
```
