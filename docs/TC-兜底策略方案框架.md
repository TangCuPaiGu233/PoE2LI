## 一、决策前提

NAS 补跑完成后，根据以下三个指标判断是否需要兜底，以及兜底范围：

| 指标 | 数据来源 | 判断阈值 |
|------|----------|----------|
| TC 文件覆盖率 | `verify_tc_export.py` 输出 | < 100% 即需评估 |
| P0 表 TC 行数比例 | `verify_tc_export.py` ratio | < 50% 触发兜底讨论 |
| P0 表关键字段存在率 | `verify_tc_export.py` fields | < 80% 触发字段级兜底 |

**决策节点**：朝露 + 远岫 + 拾遗 三方对齐后进入实施。

---

## 二、兜底选项矩阵

| 选项 | 适用场景 | 实施成本 | 数据质量 | 风险 |
|------|----------|----------|----------|------|
| **A. EN 为底，TC 缺失时降级显示 EN** | TC 客户端侧确实无翻译 | 低 | 中 — 繁体用户看到英文 | 体验降级，但信息完整 |
| **B. EN 为底 + SC 映射兜底** | TC 缺失但 SC 有对应翻译 | 中 | 中高 — 简体译名替代繁体 | 译名不统一（简/繁混用） |
| **C. 社区/第三方映射补充** | 部分表有社区繁体翻译资源 | 高 | 不确定 — 需人工校验 | 版权、准确率、维护成本 |
| **D. AI 生成 TC 翻译** | 小批量核心表缺失 | 中 | 低中 — 依赖 LLM 质量 | 幻觉风险，需人工抽检 |
| **E. 功能级降级提示** | 大面积 TC 缺失时 | 低 | N/A | 繁体用户明确感知到功能受限 |

---

## 三、推荐决策路径

```
NAS 补跑结果
    │
    ├─ TC 100% 覆盖 → 无需兜底，进入入库+CI 校验
    │
    ├─ TC 覆盖率 80%-99%，P0 表 ratio ≥ 50% → 选项 A（局部降级）
    │     └─ 对缺失表在 RAG/tooltip 侧加 "仅英文" 标记
    │
    ├─ TC 覆盖率 50%-80%，或 P0 表 ratio 20%-50% → 选项 B（SC 映射）
    │     └─ 建立 SC→TC 映射表，入库时作为 fallback
    │     └─ 仅限核心表，不扩大范围
    │
    ├─ TC 覆盖率 < 50%，或 P0 表 ratio < 20% → 选项 A + E 组合
    │     └─ 大面积降级显示 EN
    │     └─ 繁体用户入口加提示："部分内容仅提供英文"
    │
    └─ 若后续发现社区翻译资源 → 评估选项 C/D，列入 Sprint 2+ 研究项
```
