## 🔴 已确认的矛盾

### C1: Trade 集成到聊天 — HANDOVER.md 落后于实际状态

| 文档 | 声称 | 
|------|------|
| **HANDOVER.md** §一 | "Trade 集成到聊天 — **未开始**" |
| **HANDOVER.md** §七 | "Trade 集成到 AI 聊天 — **未开始**" |
| **CLAUDE.md** · M6 | "Chat + trade — **✅**" |
| **CLAUDE.md** · Agent 架构 | Chat Agent 工具层包含 `trade_search`，ReAct/Orchestrator 均可调用 |

**根因**: HANDOVER.md 是 2026-06-08 的开发交接Snapshot。当时 `trade_agent.py` 已有 `/trade/search` REST 端点，但 Chat Agent 通过 ReAct 调 trade_search 的功能刚成型被纳入。文档未反映后端 Agent 层的实际能力。

**实际状态**:
- 后端 Agent 层（ReAct/Orchestrator）✅ — Chat 中 LLM 可通过 `trade_search` 工具执行交易搜索
- 前端专属 Trade 搜索页面 ❌ — 领域无独立 `/trade` 页面，但 Chat 中已可触发搜索（通过 SSE 返回 `trade_result` 事件）
- 见 ADR-0002 中描述的完整流程

**修复**: HANDOVER.md §一 改为 "已实现（Agent层）" + 加注说明前端 Trade 页面待 Sprint 2

## 📐 文档版本对齐机制

### 原则（远期已批准）

| 优先级 | 文档 | 用途 | 更新责任 |
|:------:|------|------|---------|
| P0 | **CLAUDE.md** | 活跃架构参考 / 系统事实源 | 远岫（架构师） |
| P1 | **ADR-XXXX** | 架构决策记录，不可修改（只能 supersede） | 远岫 |
| P2 | **HANDOVER.md** | 历史快照 — 标注日期和时效范围 | 织墨（PM）在交接时更新 |
| P3 | **工程细节文档2.0** | 产品规格 — 权威需求定义 | 朝露（CEO） |

### 解决冲突的流程

1. **发现矛盾** → 创建 `docs/B4-文档对账报告.md`（本文件格式）
2. **诊断** → 标注每项的根因、实际状态、修复方案
3. **修复** → 更新 P0 文档（CLAUDE.md）使其正确反映现状
4. **归档** → 标注 P1/P2 文档为历史快照，加注时效说明
5. **Review** → 织墨→远岫 15min review → 锁定

### 防止未来矛盾的机制

1. 所有文档头部强制加 `最后更新` + `时效范围` 字段
2. HANDOVER.md 等历史文档在头部用框注明确认文档性质：
   > **⚠️ 历史快照**：本文件描述的是 {date} 时的项目状态。
   > 当前实际状态以 CLAUDE.md 为准。
3. 任何架构变更必须同步更新 CLAUDE.md（远岫负责）
4. 新 ADR 在 Supersedes 字段中引用被替代的旧文档/旧 ADR
